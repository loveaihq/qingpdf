# 第 5 层任务单：最难的三样

前四层已完成。第 5 层按用户定的顺序做，每步一个实现、一次简短审查：

| 小步 | 内容 |
|---|---|
| **5a（本单细写）** | 改原有的文字（阅读器里点一行改；命令行查找替换） |
| 5b | PDF 转 Word（.docx） |
| 5c | 扫描件识别文字（用 Windows 自带的文字识别接口） |

共同规则同第 4 层：增量保存、原文件字节不动、加密文件用原密钥、"允许修改内容"权限、有签名的文件不许改内容；编辑走 `qingpdf_core::view` 接口；`unsafe` 只在 `win32.rs`；不加依赖；阅读器 ≤ 3.6 MB（2026-10-12 用户定，原来是 3.3 MB；编辑代码在按体积编译的 `qingpdf-core` 里）。

## 5a 改原有的文字

规范：ISO 32000-1 9.4（文字对象和操作符 `Tj`/`TJ`/`'`/`"`）、9.3（文字状态）、9.10（文字到 Unicode）、7.8（内容流）、8.10（表单 XObject）。

1. **真的删掉原来的字**：改哪段就把那段字形从内容流里去掉（必要时拆开 `TJ` 数组），不是盖一个白框。改完后提取文字只得到新内容，旧内容在文件的新版本里不再存在（旧版本仍在增量更新之前的字节里，这一点在界面和文档里说明，需要彻底去掉时用"另存为"整份重写）。
2. **内容流改写**：只改动受影响的那几个操作符，其余字节原样保留；在表单 XObject 里的文字，被多页共用时只给当前页复制一份再改。
3. **新文字的字体**：
   - 原字体里有所有需要的字形就用原字体（按 ToUnicode 反查编码；简单字体按编码表）；
   - 缺字时用 4b 的字体子集嵌入一个相近的系统字体（衬线/无衬线/等宽按原字体的 `/Flags` 和名字挑，中文宋体/黑体/楷体/仿宋对应），字号、颜色、字间距、水平缩放、文字矩阵沿用原来的。
4. **范围**：一次改一行（同一文字矩阵下连续的一段），不做跨行重排；新文字比原来长时照样画出，超出原来宽度时提示。
5. **阅读器**："编辑文字"工具：点一行出现编辑框（中文输入法），回车确认，Esc 取消；能撤销。
6. **命令行**：`qingpdf replace a.pdf --find "旧词" --replace "新词" [--pages 1-3] -o out.pdf`，报告替换了几处；找不到时退出码非零。
7. **限制**：每次改写的内容流大小、一页的改动次数、查找替换的总处数都设上限，计入工作计量器。

## 5a 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。
2. 中文公文、英文论文、竖排页、文字在表单 XObject 里的页各改一处：`qpdf --check` 通过；PDFium 和 MuPDF 都显示新文字、位置和字号与原来一致；PDFium 提取文字得到新内容、得不到旧内容；原文件字节是前缀。
3. 原字体缺字和不缺字两种情况都测；加密文件（AES-256）测一个。
4. `qingpdf replace` 在 468 页的书上替换一个常见词 ≤ 3 秒。
5. `qingpdf-view.exe` ≤ 3.3 MB。
6. 一次简短审查通过。


## 5b PDF 转 Word

规范：ISO/IEC 29500（Office Open XML，只用 WordprocessingML 的常用部分：段落、文字格式、标题样式、列表、表格、图片、分节和分页）；输入端用第 2 层的文字和位置、第 3 层的图片。

1. **输出 .docx**：自己写 zip 容器（用已有的 Flate 压缩）和 XML 部件（`[Content_Types].xml`、关系文件、`document.xml`、`styles.xml`、`numbering.xml`、`media/`、`docProps/core.xml`）。不加依赖。
2. **版面分析**（自己写，放在按体积编译的 `qingpdf-core`）：
   - 行合成段落（按行距、缩进、对齐）；按字号和粗细认出标题，用 Word 的标题样式；
   - 认出多栏（论文两栏）并按阅读顺序输出；页眉页脚、页码不进正文（放进 Word 的页眉页脚或丢掉）；
   - 项目符号和编号列表；
   - 表格：有框线的表格（来自页面上的线条和矩形）输出成 Word 表格，单元格里的文字放对；没框线的先当普通段落；
   - 图片：页面上的图片按位置放成嵌入图片（JPEG 原样，其他编成 PNG）；
   - 中文：东亚字体（宋体、黑体等，`w:eastAsia`）、全角标点不加多余空格；竖排页用竖排分节。
   - 扫描件（整页只有图片）先整页放图片，5c 再加识别出的文字。
3. **命令行**：`qingpdf docx a.pdf [--pages 1-10] -o a.docx`。**阅读器**：文件菜单"导出为 Word"。
4. **限制**：页数、字符数、图片大小、输出大小设上限，计入工作计量器；坏文件不崩不卡。

## 5b 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。
2. 结构正确：输出的 zip 和每个 XML 部件都能解析，关系和内容类型齐全（写一个 Python 检查脚本）；如果本机装了 Word 或 LibreOffice，用它打开一份确认（不装新软件）。
3. 内容正确：中文公文、英文两栏论文、带表格的文件、带图片的文件各转一份。从 docx 里取出的文字和 `qingpdf text` 的结果一致（顺序、不丢字）；标题、表格、图片数量对得上。
4. 速度：100 页的论文转换 ≤ 3 秒。
5. `qingpdf-view.exe` 增加 ≤ 0.15 MB（给 5c 留出地方）。
6. 一次简短审查通过。


## 5c 扫描件识别文字

用 Windows 自带的文字识别（`Windows.Media.Ocr`，Windows 10 起就有），不自己写识别算法，不加依赖，不联网。

1. **调用方式**：在阅读器的 `win32.rs` 里自己声明需要的 WinRT 接口（`RoInitialize`、`RoGetActivationFactory`、HSTRING 函数、`OcrEngine`、`SoftwareBitmap`、`CryptographicBuffer.CreateFromByteArray` 建缓冲区、`IAsyncInfo` 轮询等待结果），不实现自己的 COM 对象。`unsafe` 仍然只在 `win32.rs`，每处注明为什么安全。
2. **语言**：优先用用户的语言（中文）。系统里没装中文识别时，提示用户在"设置 → 时间和语言 → 语言"里添加中文语言包（我们不去改系统设置），并列出现有可用的语言。
3. **识别哪些页**：没有文字、主要是图片的页（扫描件）。把页面按适合识别的分辨率渲染（约 300 dpi，不超过识别接口的最大尺寸），送去识别。在引擎线程之外的后台做，能取消、显示进度，界面不卡。
4. **结果怎么用**：
   - 识别出的字按位置写成**看不见的文字层**（`Tr 3`），盖在扫描图上，用 4b 的字体子集，每个词用水平缩放对齐到识别框的宽度；
   - 保存后，别的软件也能搜索和复制这些字；我们自己的搜索、选字复制、转 Word（5b 留下的扫描件页）都用上它；
   - 用增量保存，原文件字节不动；权限按"允许修改内容"，有签名的文件不改内容（只在内存里用，不保存）。
5. **阅读器**："工具 → 识别文字"：识别全部扫描页或当前页。
6. **限制**：每页识别的图片大小、每次识别的页数、文字层大小设上限；识别接口出错或超时（单页 30 秒）就跳过那页并提示。

## 5c 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。和 Windows 识别接口打交道以外的逻辑（选哪些页、文字层生成、坐标换算）能单独测。
2. **准确度**：把语料库里的中文公文（有文字的）渲染成图片、做成只有图片的 PDF，识别后和原文字比，中文字符准确率 ≥ 95%；英文论文页同样做一次。
3. 语料库里真正的扫描件（JBIG2、JPX、黑白传真的各一个）识别后能搜到页面上的词；保存后用 PDFium 提取得到识别的文字，`qpdf --check` 通过，原文件字节是前缀。
4. 速度：A4 扫描页识别一页 ≤ 2 秒（接电源）。
5. `qingpdf-view.exe` ≤ 3.6 MB。
6. 一次简短审查通过。


## 5d PDF 转 Excel（2026-10-13 用户加）

规范：ISO/IEC 29500 的 SpreadsheetML 常用部分（`workbook.xml`、`worksheets/sheetN.xml`、`sharedStrings.xml`、`styles.xml`、`mergeCells`、数字格式）。复用 5b 的 zip 写出、表格检测、版面分析。

1. **找表格**：
   - 有框线的表格：用 5b 已有的检测；
   - **没有框线的表格**（银行流水、财务报表常见）：按文字的对齐找列（多行在同一横坐标附近对齐、列之间有稳定的空隙），按行距分行；跨行的单元格（一格里折成两行的字）合到一起。这部分写成独立的函数，5b 转 Word 也改用它（没框线的表格不再当普通段落）。
2. **写 Excel**：每个表格一个工作表（工作表名"第3页-表1"之类，不超过 31 个字符、不含非法字符）；没有表格的页不输出，整个文件都没表格时把每页文字按行放进一个工作表并提示。合并单元格照搬。
3. **数字**：整数、小数、千分位（`1,234.50`）、负数（`-12`、`(12)`）、百分比、带货币符号（`¥`、`$`）的金额存成数字并设对应格式；日期（`2024-05-01`、`2024年5月1日`）存成日期；认不准的（如身份证号、以 0 开头的编号、超过 15 位的数字）保持文本，防止 Excel 改坏。
4. **入口**：命令行 `qingpdf xlsx a.pdf [--pages] -o a.xlsx`；阅读器文件菜单"导出为 Excel"（能取消）。
5. **限制**：表格数、单元格数、单元格文字长度、输出大小设上限，计入工作计量器；坏文件不崩不卡。

## 5d 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。
2. 结构：输出的 zip 和每个 XML 部件能解析、关系和内容类型齐全（扩展 `tests/tools/docx_check.py` 或另写 `xlsx_check.py`）。
3. 内容：语料库里有框线的表格文件、一个没框线的表格（没有就用 PDF 生成一个银行流水式的测试文件）各转一份：行列数对、单元格文字和 `qingpdf text` 一致、金额和日期是数字类型、编号和长数字仍是文本。
4. 速度：100 页的表格文件 ≤ 3 秒。
5. `qingpdf-view.exe` ≤ 3.6 MB。
6. 一次简短审查通过。

## 不做

跨行或整段重排、改字体样式（加粗斜体）、改扫描件上的字（那是图片）、彻底清除历史版本（用整份重写的"另存为"）。

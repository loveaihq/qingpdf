# 第 4 层任务单：编辑

第 1–3 层已完成（文件结构、加密、文字、渲染、阅读器）。第 4 层让用户能改 PDF。分三小步，每步一个实现、一次简短审查：

| 小步 | 内容 |
|---|---|
| **4a（本单细写）** | 增量保存、撤销重做、批注：高亮/下划线/删除线/波浪线、手写、便签 |
| 4b | 字体子集嵌入、填表（含中文）、放签名图片、文字框批注 |
| 4c | 加文字、图片、水印（阅读器和命令行都能用） |

共同规则：
- 保存用**增量更新**（ISO 32000-1 7.5.6）：只在文件末尾追加改动，原来的字节一个不动。先写到临时文件再改名替换，失败时原文件不受影响。
- 加密文件的追加内容用原来的密钥加密；权限按第 1.5 层的做法：没有所有者密码时，禁止改批注的文件不能加批注，禁止填表的不能填表。
- 新加的批注和表单都**自己生成外观流**，别的阅读器打开看到的一样。
- 编辑功能走 `qingpdf_core::view` 的消息式接口（以后鸿蒙版也用），更新 `docs/view-api.md`。`unsafe` 仍然只在 `win32.rs`，不加依赖。

## 4a

规范：ISO 32000-1 7.5.6（增量更新）、7.5.8（交叉引用流：原文件用流的，追加部分也用流）、12.5.2（批注字典）、12.5.6.4（Text 便签）、12.5.6.10（文字标记：`/QuadPoints`）、12.5.6.13（Ink 手写）、12.5.6.14（Popup）。

1. **写回端**：在 `writer.rs` 旁边加增量写：新对象和改过的对象追加在后面，新交叉引用段的 `/Prev` 指向原来的，`/ID` 第一项不变、第二项更新。原文件是交叉引用表的就追加表，是流的就追加流，混合文件按 7.5.8.4 处理。
2. **批注**：
   - 高亮、下划线、删除线、波浪线：用 3d-2 的选字结果生成 `/QuadPoints`，颜色可选；
   - 手写（Ink）：鼠标拖动画线，线宽和颜色可选，点数设上限；
   - 便签（Text + Popup）：点一下放图标，弹出框输入文字（中文输入法），文字存在 `/Contents`；
   - 选中已有的批注可以删除（包括别的软件加的）；
   - 每种都生成外观流，`/M`、`/CreationDate`、`/T`（作者名，默认用 Windows 用户名，可改）按规范写。
3. **撤销和重做**：Ctrl+Z / Ctrl+Y，按操作记录，保存前都能撤销。
4. **保存**：Ctrl+S 增量保存到原文件；"另存为"保存到新文件；有没保存的改动时关闭窗口要问。
5. **命令行**：不加新命令（4c 再加）。

## 4a 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。
2. 每种批注保存后：`qpdf --check` 通过；PDFium 和 MuPDF 渲染出来都能看到，位置和颜色正确；我们自己重新打开也一样；原文件的字节确实一个没动（比较前缀）。
3. 加密文件（RC4、AES-128、AES-256 各一个）加批注保存后，用密码能打开，批注能看到。
4. 原文件用交叉引用流和混合交叉引用的各测一个。
5. 100 页的文件加一个批注后保存 ≤ 200 毫秒；`qingpdf-view.exe` 增加 ≤ 0.3 MB。
6. 一次简短审查通过。


## 4b

规范：ISO 32000-1 9.6.4 / 9.7（嵌入 TrueType 子集为 CIDFontType2，`Identity-H`，`/W` 宽度，`/CIDToGIDMap /Identity`）、9.10.3（ToUnicode）、12.7（交互表单：字段、`/DA`、`/Q`、`/MaxLen`、`/Ff`、外观流生成 12.7.3.3）、12.5.6.6（FreeText）、12.5.6.12（Stamp）。

0. **先瘦身**：阅读器已经 3.01 MB，离 3.3 MB 只剩约 0.3 MB。先查清楚体积花在哪（链接器 `/MAP` 之类），在不让 `perf` 和 `--bench` 变慢的前提下，至少省出 0.15 MB（比如界面代码按体积优化、去掉重复的代码和表）。省下多少写进报告。
1. **字体子集嵌入**（写新内容都要用）：从系统字体（宋体、微软雅黑、Arial 等 TrueType，含 TTC 里的某一个）取出用到的字形，写成子集嵌进文件，带 ToUnicode，复制出来的文字正确。遵守字体的嵌入许可（OS/2 `fsType`：禁止嵌入的不嵌，改用别的字体并提示）。只做 TrueType（`glyf`）字体；系统里只有 CFF 字体时提示。
2. **填表**：文本框（单行、多行、等宽格 comb、最大长度，中文输入法）、勾选框、单选、下拉和列表。按 `/DA` 和 `/Q` 自己生成外观流；字号为 0 时自动缩放。Tab 键在字段间切换。
   - 没有外观的字段（`NeedAppearances`）打开时生成外观（补上 3c2-3 留下的差距）；
   - 表单里的 JavaScript 不执行（格式化、计算都不跑），在 decisions.md 记一笔。
3. **放签名图片**：选一个 PNG 或 JPEG（用已有的 `image.rs`），放到页面上、能拖动和缩放，存成 Stamp 批注（PNG 透明部分保持透明）。
4. **文字框批注**（FreeText）：用嵌入的子集字体，中文能输入。
5. **权限**：填表按"允许填表"位，签名图片和文字框按"允许改批注"位；DocMDP P=2 只允许填表。
6. **限制**：字段个数、外观生成的工作量、子集字体大小、图片像素都设上限，计入工作计量器。

## 4b 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。
2. 中文表单填好、加一个中文文字框和一张签名图片后保存：`qpdf --check` 通过；PDFium 和 MuPDF 都正确显示中文（用的是我们嵌进去的字体）；用 PDFium 提取文字和填进去的一致（ToUnicode 正确）；原文件字节是前缀。
3. 原来没有外观的表单（语料库里 3c2-3 提到的那几个）打开后能看到字段内容，和 PDFium 对照。
4. 速度：500 个字段的表单打开 ≤ 1 秒；填一个字段并保存 ≤ 200 毫秒。
5. `qingpdf-view.exe` 做完 4b 后总共 ≤ 3.3 MB。
6. 一次简短审查通过。

## 不做

数字签名（证书）、改原有的文字（第 5 层）、批注的回复和审阅状态、导入导出批注（FDF/XFDF）。

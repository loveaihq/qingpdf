# 第 1 层：文件结构

做完后应该有一个命令行工具 `qingpdf`：能读懂 PDF 的内部结构，能修复常见的损坏，能把文件原样或改动后写回去。这一层不画页面，也不提取文字。

## 交付

### 1. 项目骨架

- Cargo 工作区：`crates/qingpdf-core`（引擎，库）和 `crates/qingpdf-cli`（命令行，生成 `qingpdf.exe`）
- Rust 2024 edition，用 `rust-toolchain.toml` 锁定安装时的稳定版
- `LICENSE-MIT`、`LICENSE-APACHE`、`.gitignore`
- `git init`，仓库内设置 git 身份为 `Vincent <loveaihqhq@gmail.com>`（和 evdock 一样，不用工作邮箱）
- 第一次提交只含骨架和文档

### 2. 规范

- 以 ISO 32000-1:2008 为准，用 Adobe 免费公开的版本 `PDF32000_2008.pdf`，存到 `docs/spec/`，只放本地，不提交（版权）。
- PDF 2.0（ISO 32000-2:2020）可以从 PDF Association 免费拿，但要填登记表，由你自己去下载；有了就一并放进 `docs/spec/` 作对照。
- 下面列的细节如果和规范不一致，以规范为准并告诉我。代码里涉及规范的地方注明章节号，比如 `// ISO 32000-1 7.5.4`。

### 3. 对象模型（规范 7.3）

布尔、整数、实数、字符串（字面和十六进制两种）、名字、数组、字典、数据流、空值、间接引用。

### 4. 解析（规范 7.2、7.3、7.5）

- 词法：空白、分隔符、注释、各种转义
- 间接对象 `n g obj … endobj`
- 文件头、交叉引用表、trailer、`startxref`
- 增量更新：沿 `/Prev` 读多段交叉引用，后面的覆盖前面的
- 交叉引用流（7.5.8）和对象流（7.5.7）：PDF 1.5 以后很常见，必须支持
- **按需读取**：打开文件时只读交叉引用和页面树，对象用到时才解析

### 5. 过滤器（规范 7.4）

- 第 1 层只需要解码 `FlateDecode`，包括 PNG 预测器（7.4.4.4，交叉引用流常用）
- 其他过滤器不解码，原样保留字节，复制时照搬

### 6. 损坏修复

- `startxref` 或交叉引用表坏了：扫描整个文件找 `n g obj`，重建交叉引用
- 修复过的文件，`info` 里标明"已修复"
- 不管文件多烂，结果只有两种：打开成功，或者返回明确的错误。不许 panic，不许卡死：
  - 引擎代码里不许对来自文件的数据用 `unwrap()`/`expect()`（用 clippy 规则强制）
  - 数组和字典的嵌套深度设上限
  - `/Prev` 链、页面树里的循环引用要能检测出来

### 7. 页面树（规范 7.7.3）

- 目录 → 页面树 → 页面
- 可继承属性要正确继承：`Resources`、`MediaBox`、`CropBox`、`Rotate`（7.7.3.4）。拆分和合并时，继承来的属性要写到页面本身上，否则页面拿出来会丢东西。

### 8. 写回

- 写一个全新的文件：经典交叉引用表，只写用得到的对象，对象重新编号
- 原有的数据流按原字节照搬，不解码再压缩
- 新生成的数据流用 Flate 压缩
- 输出文件已存在时拒绝覆盖，加 `--force` 才覆盖

### 9. 命令

| 命令 | 作用 |
|---|---|
| `qingpdf info a.pdf` | 版本、页数、每页尺寸、文档信息、是否加密、是否用了交叉引用流和对象流、是否修复过 |
| `qingpdf merge a.pdf b.pdf … -o out.pdf` | 按顺序合并 |
| `qingpdf split a.pdf --pages 1-3,5 -o out.pdf` | 取出指定页 |
| `qingpdf split a.pdf --every 10 -o out_%d.pdf` | 每 10 页拆成一个文件 |
| `qingpdf delete a.pdf --pages 2,4-6 -o out.pdf` | 删页 |
| `qingpdf rotate a.pdf --pages 1-3 --angle 90 -o out.pdf` | 旋转，只接受 90 的倍数 |
| `qingpdf img2pdf 1.jpg 2.png … -o out.pdf` | 每张图一页 |

- **合并**：只合并页面和页面用到的资源。后面几个文件的书签、表单、附件这一层先不合并，输出里提示用户丢了什么。
- **图片转 PDF**：
  - JPEG 不解码，原样嵌入（`DCTDecode`），只读文件头拿宽高和颜色通道数
  - PNG 解码后用 Flate 重新压缩，透明通道做成 `SMask`
  - 默认页面是 A4，图片等比缩放后居中；横图自动用横向 A4。加 `--page fit` 时页面等于图片大小。
- 路径里有中文、空格要能正常用。
- 命令行提示用英文（面向所有用户）。图形界面到第 3 层再做中英双语。

### 10. 测试文件

- `tests/corpus/public/`：从 pdf.js（Apache-2.0）和 PDFium 的测试文件里挑，每个都核对许可证，在 `tests/corpus/SOURCES.md` 里记来源和许可证
- 中文组：至少 10 个，覆盖公文、论文、电子书、竖排、扫描件。能公开的放仓库；含个人信息的放仓库外面，用环境变量 `QINGPDF_PRIVATE_CORPUS` 指过去
- 坏文件：写一个脚本，从正常文件生成截断的、`startxref` 偏移被改的、交叉引用表被乱改的版本

### 11. 依赖

只加这两个，再要加别的先说明理由：

- `miniz_oxide`（MIT）：Flate 压缩解压
- `png`（MIT/Apache）：图片转 PDF 用

命令行参数自己解析，不用 clap（体积）。

## 验收

1. `cargo test` 全部通过，`cargo clippy` 没有警告，贴出输出。
2. **往返测试**：测试库里的每个文件都读进来、写回去、再读一遍，页数一致，每页内容流的字节一致。贴出汇总。
3. **独立工具核对**：所有输出文件过一遍 `qpdf --check`（Apache-2.0，只用于测试，不进产品；需要另外安装），全部通过。再抽 5 个用 Chrome 打开截图。
4. **坏文件测试**：每个坏文件要么修复后打开，要么返回明确的错误；没有一个 panic，没有一个超过 5 秒。贴出汇总。
5. **性能**，在你这台电脑上量，贴出数字：
   - `info` 一个 1000 页的文件 ≤ 0.3 秒
   - 合并两个 500 页的文件 ≤ 2 秒
   - release 版 `qingpdf.exe` ≤ 3 MB
6. 独立 subagent 的审查意见和处理结果。审查对照规范逐条核对解析和写回的要求。
7. `docs/decisions.md`：规范没写清、或者自己做了选择的地方，都记下选了什么、为什么。

## 不做

- 渲染（第 3 层）、提取文字（第 2 层）、任何编辑（第 4 层）
- 加密的 PDF：检测到就明确提示"暂不支持加密文件"，正常退出
- 合并书签、表单、附件
- 输出端的优化：不生成对象流和交叉引用流，不做"快速网页查看"线性化

# 第 3 层任务单 3d：阅读界面

渲染已经全部完成（3a–3c2），3d 做一个真正的阅读器。

## 已定（2026-10-10，用户确认）

- **界面全部自己写**，直接用 Windows 自己的窗口、菜单、输入框（中文输入法天然没问题），不用任何界面库。连 Windows 函数的声明也自己写（不用 windows-sys），所以不增加依赖。
- **单独一个 `qingpdf-view.exe`**：双击就是阅读器，不弹命令行窗口。`qingpdf.exe` 继续当命令行工具，不变。
- **unsafe 只许出现在界面的一个模块里**（`win32.rs`，调用 Windows 函数必须用），每处写明为什么安全。引擎 `qingpdf-core` 仍然禁止 unsafe。
- **引擎接口按"以后能接鸿蒙"来设计**：界面只通过一套消息式接口和引擎打交道，以后鸿蒙版（ArkTS 界面）用同一套接口。

分两小步，每步一个实现、一次简短审查：

| 小步 | 内容 |
|---|---|
| **3d-1** | 引擎接口、窗口、打开文件、滚动缩放、渲染缓存、总内存上限、硬规矩测速 |
| 3d-2 | 书签目录、搜索、选字复制、链接、最近文件、打印 |

## 3d-1

1. **新 crate `crates/qingpdf-view`**，Windows 子系统。清单（manifest）用链接参数嵌进去：Common Controls 6、按显示器 DPI（PerMonitorV2）。只用 `W` 结尾的 Unicode 函数。画页面用 `StretchDIBits` 一类 GDI 函数把渲染好的位图贴上去，不用 Direct2D。
2. **引擎接口**（放在 `qingpdf-core`，比如 `view` 模块）：一个引擎线程独占文档，界面发请求、收结果：
   - 打开（文件字节、密码）、页数、每页大小；
   - 渲染请求（页、缩放、页内区域、优先级），可以取消；结果是 BGRA 位图；
   - 接口里不用 Rust 特有的类型，以后能包成 C 接口或鸿蒙的 NAPI。在 `docs/` 里写一页接口说明。
3. **窗口功能**：
   - 打开文件：Ctrl+O 系统对话框、拖进窗口、命令行参数；加密文件弹密码框（密码不写日志、不存盘）；
   - 连续竖向滚动；缩放：适合宽度、适合整页、Ctrl+滚轮、Ctrl+加减号，10%–800%；
   - 键盘：PgUp/PgDn/Home/End/方向键；显示页码，可以跳页；旋转视图；
   - 界面文字按系统语言用中文或英文。
4. **渲染调度**：先画看得见的页，再画前后相邻的页；先出低分辨率预览，再出清晰的；滚动或缩放时取消过时的请求；缩放过程中先拉伸已有的位图，停下来再重画。位图缓存按字节数设上限。
5. **总内存上限**：一个总预算（200 MB）统管文件本身、引擎的各种缓存和位图缓存，超了先丢最远的页。3c2 留下的问题（画布、JPX 解码器、缓存各自有上限但总和可能超 200 MB）在这里解决。
6. **坏文件**：渲染在引擎线程上，界面永远不卡。某页出错或超了工作量，就显示已画出的部分，加一条细提示。
7. **自动测速**：阅读器加一个隐藏参数（比如 `--bench a.pdf`），自己打开、按程序滚过所有页、记下各项时间和内存峰值后退出，不用人手点。

## 3d-1 验收

1. `cargo test --release` 全部通过，`cargo clippy` 无警告。布局、缩放、缓存的逻辑和 Windows 调用分开写，能单独测。
2. **硬规矩**（接电源时用 `--bench` 量，100 页的文件，语料库里找）：
   - 启动到第一页显示 ≤ 1 秒（争取 ≤ 0.3 秒）；
   - 翻一页 ≤ 100 毫秒；
   - 从头滚到尾，内存峰值 ≤ 200 MB；
   - `qingpdf-view.exe` ≤ 3.3 MB（引擎大约 2.8 MB，界面部分 ≤ 0.5 MB）。
3. 在本机实际打开几份中文公文、扫描件、加密文件，截图看过。
4. 一次简短审查通过。

## 3d-2（下一单再细写）

书签目录侧栏、搜索（Ctrl+F，用第 2 层的文字位置，结果高亮）、选字和复制、链接（内部跳转；外部网址先问再打开）、最近打开的文件和上次看到的页（存在 `%APPDATA%\qingpdf`，不联网）、打印。

## 不做
